# The first real measurement — two links, taken from the mesh, with no operator involvement

**Date:** 2026-10-31 · **Where:** Rob's house · **How:** a mesh job per machine, reading the adapter's negotiated
link speed. No Location permission needed, no command typed by Rob.

## The raw evidence

`win` (laptop) — two Wi-Fi adapters up:

```
Name      : Wi-Fi 2            Name      : Wi-Fi
Status    : Up                 Status    : Up
LinkSpeed : 72.2 Mbps          LinkSpeed : 866.7 Mbps
MediaType : Native 802.11      MediaType : Native 802.11
```

`win-2` (Legion) — **on Ethernet, Wi-Fi disconnected**:

```
Name      : Wi-Fi              Name      : Ethernet 2
Status    : Disconnected       Status    : Up
LinkSpeed : 866.7 Mbps         LinkSpeed : 1 Gbps
```

## What the rates say, and what they do not

**A negotiated rate is not a stream count** — it is streams × modulation × bandwidth. Reading it needs the band
and the channel width, which these commands did not report:

| rate | most likely interpretation | confidence |
|---|---|---|
| **866.7 Mbps** | **2 streams**, 802.11ac, **80 MHz**, 5 GHz | high — 866.7 is the canonical 2 × 433.3 |
| **72.2 Mbps** | **1 stream**, 802.11n, **20 MHz**, 2.4 GHz | high — 72.2 is the canonical 1 × 1 |

So the sample is **2 streams on the 5 GHz-class link, 1 stream on the 2.4 GHz-class link**, at unknown positions.

## The comparison

The model's ceiling for a room of this size at 20 dB is **3–4 of 4 streams**, with the documented expectation
that hardware agrees **fewer** because of channel sounding.

**Observed: 2. Not falsified.** The shortfall is 1–2 streams, which is inside the documented gap — the *low-side*
falsifier (a measurement exceeding the ceiling) did not fire, and the *high-side* one (a mean shortfall ≥ 2) is
borderline with a single sample and cannot be judged on one row.

**And the 1-stream link is not a failure of the model either**: at 2.4 GHz in a 20 MHz channel the mode count is far
lower, and a 1 × 1 link cannot carry more than one stream by construction.

## What this does NOT establish, stated plainly

- **No positions.** Without coordinates the *ordering* test — the one the validation harness exists for — cannot
  run. This confirms a single count is not contradicted, nothing more.
- **No band or channel reported.** The 5 GHz / 2.4 GHz reading is an inference from the rate, not a measurement.
- **One machine, two adapters.** Whether these are two radios or one radio plus a virtual adapter was not
  determined, so the two rows may not be two places.

## What Windows can and cannot report WITHOUT Location — measured, not assumed

Three candidate routes were probed on both nodes (`Get-NetAdapterAdvancedProperty`, the
`Microsoft-Windows-WLAN-AutoConfig/Operational` event log, and the legacy `MSNdis_80211` WMI class):

| what | available without Location? | evidence |
|---|---|---|
| **link speed** | **yes** | `Get-NetAdapter` → 866.7 / 72.2 Mbps |
| **SSID** | **yes** | event log: `win` → **"Pretty fly for s WiFi"**, `win-2` → **"Forest"** |
| **PHY type** | **yes** | event log: `802.11n` on `win` — which places that association in **2.4 GHz** |
| **channel number** | **no** | not in the advanced properties (those are *band preferences*, not the live channel) and not in the event log |
| **band, live** | **no** | only inferable from PHY type |

**So the probe's falsifier fired for the middle case:** band and channel are **not** obtainable from these routes
without Location. PHY type is a proxy — `802.11n` implies 2.4 GHz, `802.11ac`/`802.11ax` imply 5 or 6 GHz — and a
proxy is not a measurement, so it is labelled as one.

**And a surprise worth recording: the two nodes are associated to different SSIDs** — `Pretty fly for s WiFi` and
`Forest`. That is consistent with Rob's "there is another access point downstairs", and it means the two samples are
**two different networks**, not two positions on one.

## What the next sample needs

1. **coordinates** for the client, and the AP's;
2. **the band and channel**, which needs either Windows Location (for `netsh wlan show interfaces`) or a Linux
   client with `iw`;
3. **three or more positions**, so the ordering test has an order to test.

**Then `python3 scripts/validate_streams.py` turns it into CONSISTENT or FALSIFIED with a reason.**

## Why this counts

It is the first time this engine has been put against **a real link in a real room**, and the result was obtained
**without asking Rob to type anything** — two PowerShell statements dispatched to two nodes, one job each. That is
the standard the execution gate now enforces, and the first time it was met for a measurement rather than a
refusal.

**The model was not falsified, and the honest summary is exactly that — not that it was confirmed.**
