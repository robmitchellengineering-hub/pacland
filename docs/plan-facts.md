# The fact-builds — what to build to get answers rather than pointers

Planning room (`~/Documents/DeepSeek`), 2026-10-29. Decisions: D9 (this folder owns intent, the repo
owns code), D10 (job → plan → decision), D14 (pacland is the method at maximum difficulty), D15
(discipline-scale framing).

Companion to `docs/plan-exact-terms.md` (the checks) and `docs/is-the-landscape-chaotic.md` (the
consumer). That document asks *is the claim checkable*. This one asks a harder question:

> **Does the null outcome also count as a result?**

If a build can only produce "we found it", it is advocacy. If "we found it" and "we didn't" are both
facts, it is an instrument. Three builds pass, and the rest of the fact-shaped work does not.

## F1 — the measure engine (X7 · one day · Mac)

**The fact.** The same counting question, put to four reasonable measures on one *exactly enumerable*
lattice, gives a spread. That spread is the result: it is the measure problem stated as a number
instead of an argument. If the measures agree within 5%, that is also a result — it says the
measure-dependence is invisible at this lattice, and it is the first time this programme can say
either.

**What exists.** `windows.convergence` (from `src/pacland/exactness/`, #204) already does two measures
— flux-uniform and label-uniform — on the tadpole fraction, and measured a spread of **0.62**. That is
a demonstration. A fact needs a measure *family*, arbitrary properties, and the exact/sampled line held
honestly.

**What is missing.** A `measure` object (a weight over the flux lattice), a property as a predicate,
and a table per property. Today the second measure is hard-wired to the label distribution.

**Steps.**

1. `src/pacland/measure/lattice.py`: `enumerate_window(b3, max_abs)` (exists, cached) and
   `weights(kind, fluxes)` with the named measures — `flux-uniform`, `primitive`, `tadpole-uniform`,
   `log-uniform-in-N`, and one **model-motivated** measure (a volume proxy from the tadpole, stated as
   a proxy because `h11` is not on disk).
2. `fraction(property, measure, window)` → value; `spread(property, measures)` → min, max, ratio.
3. Properties: `0 < N <= L`, `d = 1`, `|W0| < eps` (corpus only — and only after the `V`/`W` caveat
   below), `is_susy` (corpus only).
4. **Acceptance:** a property with an analytic answer — the fraction of *all* pairs with `N > 0`, which
   can be counted two independent ways — must agree exactly with the enumeration, or the weighting is
   wrong.
5. **Falsifier:** if every property's spread is under 5%, write that. It would say the "10^500 argument
   is a statement about measures" claim is false at this lattice, which is a real answer.

**Honest limit.** Only `b3 = 6, |F_i|,|H_i| <= 1` is *exactly* enumerable here (531,441 pairs). Any
larger window is *sampled*, and must be labelled as sampled in every table. A fraction without its
window and its exactness flag is not a fact.

Window `b3 = 6, |F_i|,|H_i| <= 1`, all 531,441 pairs, exact enumeration.

**The fact:** "the fraction of flux choices with a small tadpole" is **0.071 or 0.361** depending only on
which reasonable measure is used — a factor of **5.05**, with no physics changed. That is the
"10^500 vacua" argument, quantified rather than argued.

**The acceptance test was an identity, not a number:** `fraction(N>0) == (1 - fraction(N==0))/2` holds to
`1e-16` for all five symmetric measures, and is proved able to fail by an asymmetric weight in
`tests/test_measure_engine.py`.

**A vacuous column caught in the first version:** "is the content primitive" is 1.000 under every measure
at `max_abs = 1`, because every non-zero pair there already is primitive. It was replaced by `N == 0`,
which varies. A column that cannot vary is not a finding.

## F2 — certified periods (the increment on B3's target · Mac, then node)

**Premise.** #210 probed CYTools on `pacland-rog`: it exposes `compute_gv`, `compute_gw`,
`intersection_numbers`, `compute_kappa_matrix`, `curve_basis`, `triangulation` — and **no**
`picard_fuchs_equation`, no `monodromy_matrices`, no period solver. The build is therefore real, and
#210 names its first target: the quintic, with

```
L = θ⁴ − 5z (5θ+1)(5θ+2)(5θ+3)(5θ+4),    θ = z d/dz
```

and monodromy generated by the unipotent `z → 0` generator and the conifold generator at `z = 1/5⁵`.
#210 says plainly that neither the build nor R1's literature value is done.

**What F2 adds, and why it is not a duplicate.** A solver that produces a number is not yet an
instrument. F2 is the part that makes it one: **interval bounds on every period**, the conifold
target **pinned from a citable source before use**, the index-4 monodromy matrices, and
`MᵀΣM = Σ` verified in integers.

**The facts it can produce.**

| fact | how |
|---|---|
| R1's conifold period, to a stated bound, against an independent closed form | Frobenius at the conifold point; the Γ-value is the cross-check, not the input |
| B3's covariance table as a **derivation** (gap G1) | the monodromy action on the four solutions |
| `MᵀΣM = Σ` | integer arithmetic on the generators |
| instanton numbers that must be integers | with #209's caveat: **primitive degrees only**; non-primitive degrees are expected to break integrality |
| exact masses at a real CY vacuum (after M2) | the CS metric is exact given the periods: `K = −log(i Π†ΣΠ)` |

**The null.** If the interval cannot be made tight enough to separate the conifold value from its
neighbours, that is a statement about the conditioning of the series — the same shape as the h12 wall,
and still an answer.

**Steps.**

1. **Pin the literature value first.** Locate the conifold period's closed form (the
   Candelas–de la Ossa–Font–Katz–Morrison line) in a citable source; record the exact expression, the
   normalisation convention, and the precision at which the source quotes it. **No number is used
   before this step is done** — #210's own rule, kept.
2. `src/pacland/periods/quintic.py`: the four Frobenius solutions at `z = 0` (the pure series plus the
   three with `log` terms), coefficients in `mpmath.iv`, with the tail bounded by the ratio test (the
   series is hypergeometric, so the remainder is bounded by the next term times `1/(1−r)`).
3. **Continuation to the conifold**, `z = 1/5⁵`, along a certified path or by the standard local
   expansion in `1 − 5⁵z`. Cross-check the LCS log coefficients *first* — the leading behaviour is
   known exactly, so a normalisation error is caught before the conifold is reached.
4. Compare: report the interval, the pinned value, and whether the value lies inside the interval.
5. **Monodromy:** the two generators as integer matrices on the four solutions; check
   `MᵀΣM = Σ` exactly.
6. **Acceptance:** interval width under `1e-20` at working precision; the pinned conifold value inside
   the interval; `MᵀΣM = Σ` exactly; the LCS log coefficients correct to the quoted precision.
7. **Falsifier:** a conifold value outside the interval means the normalisation or the continuation is
   wrong — and step 3 says which, before the conifold is touched.

**Where.** M1 (the quintic) is **Mac work**: the operator is closed form, `mpmath 1.3.0` with working
interval arithmetic is present, and nothing on the node is needed. M2 (the GKZ system for the toric
models, needing CYTools' polytopes and a GKZ solver) is **node work** and belongs to whoever holds the
node.

### F2 M1 — BUILT AND RUN (2026-10-29)

`src/pacland/periods/quintic.py` · `python3 scripts/quintic_periods.py` · 6 tests. The operator is
#210's: `L = θ⁴ − 5z(5θ+1)(5θ+2)(5θ+3)(5θ+4)`, `z = 1/(5ψ)⁵`.

| check | result |
|---|---|
| the Frobenius recursion against the literature coefficient | `c_n(0) = (5n)!/(n!)^5` to **1e-31** (dps 30) — exact, not fitted |
| the monodromy at `z = 0` | unipotent, **index 4** — one Jordan block, as a fourfold indicial root requires |
| the tail bound inside the radius | **1.5e-97** at `z = 0.5 z_c` with 300 terms |
| the same bound at the conifold | **9.4e-5** at `z = z_c`, ratio `r → 0.9933` |

**The finding: the conifold sits exactly on the radius of convergence.** `z_c = 1/5⁵`, and
`|c_n zⁿ/c_{n−1}z^{n−1}| → 5⁵|z|`, so `r → 1` at the conifold, the geometric bound degrades by four orders
of magnitude from `z_c/2` to `z_c`, and no practical number of extra terms certifies the conifold period.
**It needs its own local expansion.** That is the next step, and it is stated rather than worked around —
which is exactly the kind of thing this plan exists to surface before a number is published.

**Two method findings worth keeping.**

1. The **coefficient-space operator check is a tautology** — `c_n n⁴ = 5P(n−1)c_{n−1}` is the recursion
   that produced `c_n`, so "verifying" it re-derives itself. It was removed rather than kept as a green
   tick.
2. **Nested numerical differentiation at fourth order is useless** for the functional check: composing
   `θ = z d/dz` four times through `mp.diff` gave residuals of order `1e78` on a function of size 1. The
   functional check needs complex-step or symbolic differentiation, which is the next increment.

**Not claimed:** R1's conifold Γ-value. #210's rule is that it must be pinned from a citable source before
use, and it has not been — so no number is asserted.

### F2 M2a — the conifold's exponents, computed (2026-10-29)

`src/pacland/periods/conifold.py` · `python3 scripts/conifold_exponents.py` · 5 tests.

`L(u^s)` is computed exactly in `u = 1 − z/z_c` with `Θ = −(1−u)d/du`, and the indicial polynomial is

```
s (s − 1)² (s − 2)          ⇒  exponents 0, 1, 1, 2
```

**All four are integers**, so every eigenvalue of `exp(2πis)` is 1 and the conifold monodromy is
unipotent — which is what a Picard–Lefschetz transvection requires, and it is computed rather than
quoted. The **double root at 1** is where the single logarithm lives (monodromy index 2). A test proves
the polynomial is a property of `z_c = 1/5⁵` by breaking it with `z_c = 1/5⁴`.

**The local radius is `|u| < 1`** (the next singular point is `u = 1`, i.e. `z = 0`). That is the
practical consequence: unlike the `z = 0` series at the conifold, the conifold's own expansion is
bounded all the way toward `z = 0`. **So the connection is reachable**: match the two expansions at
`z = z_c/2`, where both converge, solve a 4×4 system, and the conifold periods are determined *without*
a literature constant — R1 as a computation rather than a citation.

### F2 M2b — the conifold's resonances: which branches need logarithms (2026-10-29)

The connection needs the four conifold solutions, and **three of them carry logarithms** — computed, not
discovered the hard way. The Frobenius recursion divides by the indicial polynomial at `s0 + n`, so it
collapses exactly where `P(s0 + n) = 0`, and with integral exponents that is not a corner case:

| exponent | resonances | branch |
|---|---|---|
| 0 | at n = **1, 2** | needs logs |
| 1 (double root) | at n = **1** | needs logs (and the double root adds its own) |
| 2 | **none** | **a plain power series** — the only clean branch |

So the exponent-2 solution is the one that can be written down with no log algebra at all, and the
connection's other three columns need the same jet machinery the LCS side uses, now in `u`.

**A failed attempt worth recording:** building the exponent-2 series *symbolically* in sympy (solving
each coefficient in turn) does not terminate in practical time at 24 terms — the expressions explode.
The next attempt should solve the recursion **numerically at high precision** (the system is triangular,
so `c_n = −Σ_{m<n} A[n][m] c_m / A[n][n]`), or keep the symbolic solution to a handful of terms and take
the rest numerically. That is a two-line change in approach and it saves a day.

### F2 M2c — the connection CLOSES, and the bug it caught (2026-10-29)

`src/pacland/periods/connection.py` · `python3 scripts/conifold_connection.py` · 5 tests.

**The gate:** the exponent-2 conifold branch must be a **constant** linear combination of the four z = 0
branches. Fitted at `z = 0.3…0.6 z_c` and tested at points not used in the fit:

| z (fitted) | 0.55 | 0.65 | 0.70 | 0.75 |
|---|---|---|---|---|
| relative residual | 4.0e-17 | 4.0e-16 | 1.9e-15 | **6.3e-15** |

`0.8`, `0.9`, `0.95 z_c` are reported separately: there the **conifold series' own truncation**
(`0.95^160 ≈ 3e-4`) dominates and the residual is a statement about term count, not about the physics.

**The connection coefficients** — the conifold branch in the LCS basis, with no literature constant
anywhere:

    a = (−164.426878743440, −62.602306717313, −8.127765053186, −0.356908622810)

**What the gate caught.** The first run did **not** close: 6.4e-2 at `0.7 z_c` rising to 124 at
`0.95 z_c`. The cause was the **log normalisation** of `ω₁..ω₃`: the k-th Frobenius solution is
`d^k/dρ^k (z^ρ Φ) = Σ_j C(k,j) L^j Φ^(k−j)`, and the binomial weight had been dropped, leaving `ω₂` and
`ω₃` outside the solution space. That is a defect that **no existing test could see** — the coefficient
check only validates `ω₀`, and the monodromy matrix is built independently of the series. The mutation
test in `tests/test_conifold_connection.py` divides the weight back out and requires the residual to jump
above 1e-6.

**A correction to #213.** Its `ω₂` and `ω₃` were wrong for the same reason; its checks passed because
they did not exercise them. The fix is in `as_log_parts`, so every consumer is repaired at once.

**What is not done.** Three of the four conifold branches (exponents 0, 1, 1) still need the log algebra
in `u` — only the exponent-2 branch is reachable by a clean recursion. The physical conifold period is a
combination of them, so R1's number is not yet claimed: what exists now is the machinery that produces
it, with the gate that will catch it if it is wrong.

### F2 M2d — three of the four conifold branches now connect (2026-10-29)

`src/pacland/periods/conifold_recursion.py` · 8 tests.

The recursion written as a **matrix of polynomials in `ρ`** (`A[n][m]`), validated three ways against work
that already existed: its `A[lowest][0]` is exactly M2a's indicial polynomial, its **resonance pattern is
exactly M2b's** (vanishes at `s0=0` for `n=−2,−1`; at the double root `s0=1` only for `n=−2`; never at
`s0=2`), and solving it at `ρ=2` reproduces M2c's series. That pattern is the discriminating test — a
wrong matrix passes the indicial check and fails that one.

**The double root, solved.** `c₀ = δ` with `ρ = 1 + δ` cancels the resonance, so every coefficient is
analytic in `δ`; evaluating at `±δ` gives the two branches. Each is then held to the connection gate:

| branch | connection coefficients | worst residual |
|---|---|---|
| exponent 2 (M2c) | −164.4269, −62.6023, −8.1278, −0.3569 | 2.3e-21 |
| exponent 1, series | 2.723393, 0.931695, 4.7e-12, −0.009440 | 9.0e-14 |
| exponent 1, **log** | 116.6391, 39.7344, 4.5375, 0.174336 | 1.8e-13 |

Three of four columns exist. The residuals are the conifold-series truncation at `u = 0.75` (~1e-10 at
these term counts), not the connection; that is why the tests assert `1e-9` and say so.

**One test deliberately not written.** Comparing `numeric_series` against `connection.conifold_series`
agrees to 3e-39 in a clean process but is sensitive to the ambient mpmath precision, so it is recorded in
this plan rather than made a gate: a check that depends on global state is a flake, not a control.

**Still missing: the exponent-0 branch**, and two attempts have now failed in an instructive way.

It has *two* resonances (`n = −2` and `n = −1`), so `c₀ = δ` cancels only one. Measured:

| normalisation | outcome |
|---|---|
| `c₀ = δ` | recursion regular, `d₀ = [1.0, −9.4, −6.05, −4.699…]`, but the connection reaches only **5.1e-3** |
| `c₀ = δ²` | regular but **garbage** — `d₀ = [0, 3.4e18, 2.4e18, …]` |
| `c₀ = δ³` | identical to `c₀ = δ` — a third power changes nothing |
| with a log term from `±δ` | "closes" at 1.3e-13 **with coefficients ~1e36** — a cancellation artefact, not a result |

**The diagnosis, which is the useful part.** At a resonant order the diagonal vanishes, so that order's
equation does not determine its coefficient — it determines it only at the *next* order in `ρ`. A numeric
`±δ` probe therefore reads a coefficient that is not yet determined, which is exactly why `c₀ = δ²`
returns `1e18` garbage and why the log candidate "closes" through 36-digit cancellation.

**So this is not a numeric step.** It needs the recursion carried as a **Laurent jet in `ρ`** — poles at
the resonant orders, cancelled order by order against the numerator — which is the one piece of machinery
this line has deliberately not built yet. The gate is in place to receive it: a real fourth column has
coefficients of order one, like the other three.

## F3 — the brane invariant ring (later · node · no dependency on F2)

**The fact.** Either a second exact invariant beyond the tadpole, or the theorem that there is none at
every degree. Both are prizes, which is why this is the only build on the list that can overturn the
programme's own claim.

**Why it can start before F2:** the K-theory lattice of a toric CY is *topological* —
`intersection_numbers` and `c2`, both of which CYTools exposes. No periods needed.

**Steps.** `K(X)` as a lattice with the Mukai pairing; the duality group's action on it; the invariant
ring; compare its generators with the tadpole. Then the same on a real model.

**The null.** "The tadpole is alone" is the theorem; a second generator is the refutation. Either way
the wall named in `docs/SOLVING-STRING-THEORY.md` (G4/H4) gets an answer.

## What none of these gives

The 19 Standard-Model parameters, the value of the hierarchy, or the value of Λ. "Fact" here means a
**structural** fact a stranger can check — never an experimental prediction. Keeping that sentence in
the document is what keeps the rest of it credible.
